# 브랜드 이미지 검수

작업자가 긴 문서를 해석하지 않고 **사진에서 위치를 찾고 바로 수정할 수 있는 검수본**을 만든다. 기본 구성은 **큰 현재컷 + 정확한 기준컷 + 부위 확대/번호 표시 + 짧은 수정 지시**다. 2026-10-27 사용자가 기존 브랜드 검수 방법을 이 구성으로 통합하도록 요청했다.

## 시작과 기준 선택

1. 브랜드·차수·착장·컷·현재 버전·검수 범위·산출물 위치를 확인한다. 세션과 로컬 자료에서 확인할 수 있으면 다시 묻지 않는다.
2. 현재 사용자 요청과 최신 정정 → 해당 브랜드/착장의 최신 확정 자료·피드백 → 누적 기준 → 과거 작업 사례 순으로 적용한다. 파일 수정시각만으로 최신 승인본을 정하지 않는다.
3. [브랜드별 규칙](references/brands.md)에서 해당 부분을 읽고 현행 AGENTS.md와 최신 자료를 확인한다. 특정 코디의 수량·판정·예외를 신규 작업 전체에 복사하지 않는다.
4. [근거와 기록 위치](references/sources.md)는 이력이나 기준이 부족할 때 읽는다. 이 스킬 정리 이후 지시가 있으면 우선한다.
5. 검수만 요청받았다면 검수파일과 요청된 작업장 편집을 진행한다. 그것만으로 실제 이미지 재생성·크레딧 사용·기존 이미지 교체·외부 발송까지 시작하지 않는다. 이미 승인된 후속 작업은 재확인 없이 그 범위에서 수행한다.

## 원본과 기준부터 맞추기

- 요청서에서 필요한 컷 목록을 만들고 실제 전달 파일/작업장과 역대조한다. 완료 폴더에 있는 사진만 검사하고 요청 누락을 놓치지 않는다.
- 매칭 키는 브랜드·배치·착장·품번·컬러·아우터/이너·실제 방향/포즈·버전이다. 수정 전후 번호가 달라졌으면 실제 사진으로 연결한다. 파일명이 같아도 같은 이미지/버전이라고 단정하지 않는다.
- 기준 사진의 역할을 구분한다: **제품 구조/색상**, **실착 핏/기장**, **확정 얼굴/체형**, **포즈/구도**, **배경/조명**, **고객 피드백**, **이전 수정/전달본**.
- 확정 모델은 얼굴뿐 아니라 비율 수정 버전까지 확인한다. 구버전 기준과 닮았다는 이유로 최신 기준 통과를 선언하지 않는다.
- 동일 품번·컬러 원본을 우선한다. 다른 색상·복종·모델의 보조 자료는 참고할 부위와 옮기지 않을 요소를 명시한다. 누끼를 핏 기준, 포즈 사진 속 인물을 확정 모델로 바꾸지 않는다.
- 필요한 제품 전체컷·부위 상세·실착 자료를 실제로 연다. 룰/PPT 지시를 현재 이미지에서 관찰한 오류처럼 옮기지 않는다. 미촬영·자료 부족·대상 불명확은 해당 항목만 보류하고 나머지 검수는 진행한다.

## 컷별 시각 검수

접촉시트는 누락·시리즈 불일치 탐색용이다. 품질 판정은 개별 원본과 부위 확대를 보고 내린다. 전수 요청이면 모든 컷을 확인하고 표본만 봤다면 범위를 명시한다.

| 확인 축 | 실제 대조 내용 |
|---|---|
| 제품 | 품번·컬러·구성, 로고 철자/형태/위치/크기, 봉제·절개·패널 연결, 퀼팅, 포켓·지퍼·풀러·스트링·단추·액세서리, 소재·배색 |
| 모델 | 최신 확정 얼굴·머리색·헤어, 얼굴/머리 상대 크기, 목 길이·굵기, 어깨·몸통·팔·다리 연결, 손발 크기, 얼굴·목·손 피부톤 |
| 핏·기장 | 성별·복종·지정 핏/사이즈에 맞는 어깨·품·상완·소매·밑단, 허리·힙·통·총장, 여밈·레이어 노출 |
| 포즈·구도 | 시선·고개·손·팔꿈치·다리 위치, 단축 원근, 앞/뒤/측면, 전신·상하반신·가방 등 요청 크롭, 잘림·접지 |
| 배경·조명 | 해당 컷 배경색·그라데이션·그림자, 얼굴과 의상의 빛 방향·밝기·색온도 연결, 과한 광택·얼룩 |
| 세트 | 같은 착장 정면/측면/후면/액팅 사이 얼굴·체형·피부톤·제품 구조·핏·기장 일관성 |

- 구조가 단순히 ‘있음’만 확인하지 않고 위치·크기·연결·형태까지 대조한다.
- 각도·조명·원근·주름·가림을 오류와 구별한다. 가려진 로고를 바로 누락으로 판정하지 않는다. 보이지 않는 다리·발·뒷면에 지시를 복제하지 않는다.
- 실측 없는 cm, 근거 없는 얼굴 축소율·조명 수치를 만들지 않는다. 비교 사진의 목표 위치와 관계로 지시한다.
- 비율 비교는 같은 방향과 비슷한 원근으로 한다. 표시 높이를 맞출 때 종횡비를 유지하고 정렬 방법을 기록한다. 몸을 늘여 차이를 없애지 않는다.
- 정상 주름·포즈 차이·이미 반영된 항목을 반복 재작업시키지 않는다. 반대로 ‘이전보다 개선됨’을 완료로 바꾸지 않는다.

## 사진 중심 전달

제작 전에 [배치와 짧은 지시](references/layout.md)를 읽는다.

- 한 검수 화면은 한 착장·한 컷·한 수정 주제에 집중한다. 현재와 정확한 기준을 크게 나란히 배치하고, 제품 디테일은 해당 부위를 확대한다.
- 현재는 빨강, 기준은 파랑을 기본으로 **현재/기준 라벨과 같은 번호**를 함께 쓴다. 테두리·화살표는 실제 위치를 가리키며 디테일 자체를 가리지 않는다.
- 사진 옆/아래에 `① 부위 — 어떻게 수정`을 큰 글씨 한두 문장으로 쓴다. 필요할 때만 현재 차이와 유지 요소를 각 한 줄 붙인다.
- 짧게 만든다는 이유로 제품자료·핏기준·이전 수정본·실제 전달본·최신 피드백을 없애지 않는다. 필요한 사진은 가까이, 긴 근거와 이력은 펼침/부록으로 둔다.
- 요청 형식을 따른다. 미지정 화면 검수는 사진 중심 HTML, ‘파일 하나만 전달’은 사진과 근거가 포함된 PDF 등 한 파일로 완결한다. HTML은 필요한 이미지를 포함하거나 함께 묶고 작성자 로컬 경로에만 의존하지 않는다. Figma에 올리지 말라는 요청을 지킨다.

## 판정과 수정 이력

항목별 **반영 완료 / 부분 개선 / 수정 필요 / 확인 필요 / 대상 제외**를 구분한다. 새 검수의 문제 없는 항목은 **관찰 범위 내 통과**로 기록한다. ‘디테일 보완 필요없음’은 핏·비율까지 통과했다는 뜻이 아니다.

기록에는 착장·컷/버전, 부위, 현재 차이, 수정 방향, 기준 사진/부위/버전, 유지 요소, 완료 기준, 판정, 원문 피드백과 출처를 남긴다. 화면에는 필요한 짧은 부분만 보인다. 원문과 Codex의 실행용 해석을 구별한다.

수정본은 이전본·최신 기준·잔여 피드백과 재대조한다. 얼굴 보정으로 포즈가 변했는지, 체형 보정으로 포켓·로고가 늘어났는지도 확인한다. 같은 문제 재지적 시 누락/오판/새 요구/해결 방향 변경을 구분하고 해당 브랜드 누적 기록에 날짜와 근거를 남긴다. 재지적 모두를 고객의 변심으로 처리하지 않는다.

**생성 성공, 파일 준비, 자체 검수 통과, 실제 전달, 브랜드 승인**은 다른 상태다. 최종본 표기나 과거 승인, 파일 수·해상도·이름만으로 최신 품질 완료를 선언하지 않는다.

## Figma 작업장

- 실제 편집은 현재 Figma 도구와 해당 작업 스킬 지침을 읽고 수행한다. 연결 불가면 로컬 준비/미반영 상태를 구분한다.
- 사진·참고·제목·피드백·번호·테두리·완료 자리까지 **페이지 직속 독립 레이어, 잠금 해제, 고정 좌표**. 그룹·프레임·섹션 안에 사진을 묶지 않고 Auto Layout을 쓰지 않는다.
- 여러 열, 같은 행 상단 정렬, 충분한 간격을 사용한다. 독립 제목·색 띠·테두리로 구분한다. 새 사진 추가가 기존 사진·피드백을 밀지 않게 한다.
- 사진은 한 번 클릭해 자체 선택, 식별 가능한 레이어명, 개별 PNG 내보내기를 준비한다. 선택만으로 다운로드된다고 말하지 않는다. 원본과 내보내기 픽셀을 확인하고 표시 확대를 네이티브 해상도 증가로 표현하지 않는다.
- 현재 작업 페이지를 맨 위에 두고 시작 부분을 보여준다. 명시된 페이지 보호·순서 고정 예외가 우선이다. 기존 작업장 갱신 요청에 새 페이지를 반복 생성하지 않는다.
- 수정/신규 컷 옆에 같은 식별자의 결과 추가 공간을 확보하고 기존본을 보존한다. BBC처럼 빈 사각형·규격 안내를 제거한 브랜드는 여백만 둔다. 요청하지 않은 빈 1~4차 칸은 만들지 않는다.

## 크기와 최종 확인

- **2026-10-27 이후 신규 포즈컷의 최종 규격은 모든 브랜드 공통 가로 3300 × 세로 4096px**다. 이후 별도 규격 지시가 있으면 우선한다. 과거 3000×4000·3:4 신규 생성 기준을 대체한다.
- 기존 파일·전달 ZIP·작업장 이미지를 이 규칙만으로 변환/덮어쓰지 않는다. 비교용 확대/크롭은 별도 표시본이고 제품·핏 참고는 고유 비율을 유지한다.
- 도구 실제 반환 픽셀과 최종 저장 크기를 따로 기록한다. 확대 저장을 네이티브 3300×4096 또는 원생성 4K라고 표현하지 않는다.
- 산출물을 실제로 열어 사진 크기, 번호/부위 일치, 글 잘림/겹침, 이미지 로드·선명도, 누락·중복, 파일명·방향을 확인한다. PDF는 렌더, HTML은 확대/착장·항목 전환, Figma는 선택/잠금/내보내기/좌표를 확인한다.
- 최종 응답은 결과 링크, 확인 범위, 핵심 잔여 수정·보류만 짧게 적는다. 실행하지 않은 이미지 교체나 Figma 반영을 완료했다고 보고하지 않는다.
